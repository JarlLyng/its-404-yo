Why the SP-404 MkII says “Unsupported FILE”, and how to fix it

When you import from the SD card and the screen says Unsupported FILE, the SP-404 MkII can’t read that sample’s format. Import from the card takes only 16-bit linear WAV, AIFF or MP3, and most downloaded packs are 32-bit float WAV or FLAC. Convert the sample to 16-bit WAV at 48 kHz, put it in the card’s IMPORT folder, and it imports.

The message, exactly

The screen reads Unsupported FILE, with FILE in capitals, and nothing more. Roland’s reference manual lists it among the unit’s error messages and explains it in one line, the file type isn’t supported on this unit. The action it suggests is just as short: “Check the file extension, format and folder directory.”

That points at three things, and this page takes them in the order most likely to find the cause. The format comes first, because it is the one behind most reports.

Unsupported SD Card! is a different message. It is about the card itself, not a file on it, and Roland’s advice there is to format the card. Since system version 5.50 the unit also reads SDXC cards formatted as exFAT.

What import from the SD card accepts

Roland states the rule in its support article on import formats. From an SD card the SP-404 MkII takes 16-bit linear audio, as WAV, AIFF or MP3. The SP-404MK2 App on a computer also takes FLAC and M4A, with ALAC and AAC on the Mac version only. Either way, each sample is converted to 48 kHz and 16-bit as it comes in, because that is how the unit runs inside.

FormatsWAV, AIFF or MP3
Bit depth16-bit linear (integer)
Sample rateNot part of the rule. Every import becomes 48 kHz
LengthUnder 100 ms may not import. At most 16 minutes, about 185 MB
FolderIMPORT on the card, subfolders inside it are fine

The causes, in the order to check them

1. A 32-bit float WAV

This is the usual one. Splice and most commercial packs are rendered as 32-bit float, the safe format inside a DAW, and 32-bit appears nowhere in what Roland lists as importable, on either path. The sample has to become 16-bit integer audio. The 32-bit float guide covers whether that costs you anything. It doesn’t, in short, because the unit takes every import down to 16-bit anyway.

2. FLAC or M4A

FLAC, M4A, AAC and ALAC aren’t on the SD-card list at all, at any bit depth. They import through the SP-404MK2 App, or they become WAV first. The FLAC guide has both routes and the one setting that catches people out.

3. A 24-bit WAV or AIFF

The SD-card rule says 16-bit. Roland’s table of verified formats does list 24-bit WAV and AIFF, without saying whether that covers the card or only the app, so a 24-bit file may import from the card and may not. Converting it to 16-bit settles the question, and takes nothing away that the unit wouldn’t take away on import.

4. The extension

Roland’s advice names the extension first, so check that each name ends in the format the file really is. A sample renamed by hand, or one that lost its extension on the way, is worth a second look. Finder can hide an extension, so turn on Show all filename extensions in its settings, or check the name in Get Info.

5. The folder

Samples for import go in the IMPORT folder on the card. A pack copied anywhere else won’t be where the import screen looks. Subfolders inside IMPORT are fine. On the import screen you open one by turning the VALUE knob to it and pressing VALUE.

6. Too short or too long

Roland notes that a sample shorter than 100 ms may not import, which can catch a very short one-shot. At the other end a sample can be at most 16 minutes, about 185 MB. Neither is a format problem, so converting won’t change it, and a sample that long has to be split before it goes on the card.

Getting to the import screen

For completeness, here is Roland’s route. Copy the samples into the IMPORT folder on a computer and put the card in the unit. Hold SHIFT and press pad 13 for the UTILITY menu, choose IMPORT, then IMPORT from SD-CARD, then SAMPLE. Holding SHIFT and pressing pad 14 gets you to the import menu in one step. Press an empty pad, which blinks yellow, turn VALUE to the sample and press VALUE. Hold SHIFT while you turn VALUE to pick several samples at once.

How to fix it

By hand: in a DAW, export each sample as a 16-bit WAV at 48 kHz. With ffmpeg in the Terminal, one file is

ffmpeg -i in.wav -c:a pcm_s16le -ar 48000 out.wav

and every WAV in the current folder, written to a new folder called fixed, is

mkdir -p fixed
for f in *.wav; do
  ffmpeg -i "$f" -c:a pcm_s16le -ar 48000 "fixed/$f"
done

That works one folder at a time, so a pack with subfolders needs a run in each.
